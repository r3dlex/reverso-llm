# Copilot Picker Surface-Separation Invariant

Knowledge captured during the `copilot-picker-completeness` work. The symptom
and the recovery must stay visible to anyone editing the per-provider Codex
catalogs or the `codex_sync` filter.

## The invariant

The per-provider Codex catalogs under `~/.codex-reverso/reverso/` (one
JSON file per gateway prefix) are **surface-scoped**:

| File | Owns | Slug prefix | Source of truth |
|---|---|---|---|
| `copilot.json` | Copilot-surface models served by GitHub Copilot | `copilot/<model>` | live `GET /copilot/v1/models` |
| `claude.json` | Claude-surface models served by Reverso's first-party claude adapter | `<model>` (no prefix) | live `GET /claude/v1/models` |
| `auggie.json` | Auggie-surface models served by the Auggie CLI | `auggie/<model>` | live `GET /auggie/v1/models` |
| `deepseek.json` | Deepseek-surface models served by litellm | `deepseek-<model>` | live `GET /deepseek/v1/models` |

A model's **surface** is the gateway prefix that serves it. The catalog
file is named after that surface, and the slug prefix in the catalog must
match that surface's prefix exactly.

## The antipattern (what an OMX session did)

An OMX session in a separate repo (`rib-workspace`) produced a manual
patch to `~/.codex-reverso/reverso/copilot.json` that added three
Claude-surface model IDs verbatim:

- `claude-sonnet-5`
- `claude-opus-4-8`
- `claude-haiku-4-5-20251001`

These IDs are real -- they live on the `/claude` surface, not on
`/copilot`. The patch put them in the wrong catalog, with the wrong slug
format (no `copilot/` prefix). Symptom in `/model`: three models
appeared as available under the Copilot provider, but selecting any of
them would fail at runtime because the Copilot adapter does not know
how to serve them on either the `/responses` or `/chat/completions`
path (the upstream Copilot API does not list them).

## The defense

1. **Auto-gen is authoritative.** The per-provider catalogs are
   regenerated by `reverso-codex-sync --config ~/.codex-reverso/config.toml`
   from the live gateway. A manual patch is overwritten on the next
   sync. The recovery from the antipattern is therefore always
   "delete the patch and re-run the sync."
2. **Cross-surface leakage is now caught by S2 of the
   `copilot-picker-completeness` handoff:** a live-pinning integration
   test (`tests/integration/test_copilot_picker_live.py`, gated by
   `RUN_LIVE_PICKER=1`) fetches the live gateway and asserts that the
   picker keeps every chat-route model Copilot serves. If a future
   filter narrowing drops `claude-fable-5` or any other chat-route
   model, the test fails.
3. **Slug prefix is enforced by `provider_scoped_catalog_slug`** in
   `src/reverso/protocols/model_exposure.py`. Every entry the auto-gen
   writes is prefixed with `<surface>/<model>`. A manual patch that
   omits the prefix will be replaced on the next sync.

## What to do if you see the symptom again

1. Run `reverso-codex-sync --config ~/.codex-reverso/config.toml`. The
   wrong entries will be replaced by the live, correctly-prefixed set.
2. Investigate the source of the wrong entries: which OMX session
   produced them, and which catalog file was being edited? The
   symptom usually means an OMX session is reading a cross-surface
   model list (e.g., the live `/v1/models` root, which mixes all
   surfaces) and writing it into a per-surface catalog.
3. If the wrong entries keep recurring, the OMX session needs the
   same surface-separation invariant taught to it that the catalogs
   themselves enforce.
